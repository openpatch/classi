# Exam grading with points per expectation

## Context

Today an exam ends up in classi as a single `GradeEntry` per student (a text
`value`). The points behind it live in an ODS sheet generated by the assessio
CLI (`typst-assessio/extra/assessio_cli.py`), and the filled-in
Erwartungshorizonte are produced by the same CLI. All diagnostic information
(which expectation, which task, which student, over time) is lost to classi.

This plan moves exam grading into classi and retires the assessio CLI:

- Exams live in classi and work **without Typst** (manual structure, any device).
- On **desktop**, an exam can be linked to an assessio Typst document. classi
  reads the structure and grade scale via the `typst` CLI, shows a diff against
  the current exam state, and applies it only on accept.
- Points are entered **per expectation**, on desktop and mobile.
- classi is the **single place where grades are computed**; it writes the
  resulting `GradeEntry` itself.
- The **task sheet PDF** and the **unfilled Erwartungshorizont PDF** are stored
  with the library (outside the encrypted DB). **Filled** Erwartungshorizonte
  are an export only and are never stored in classi.

Builds on the current 1.x schema (`plan_v2.md` is abandoned).

## Decisions

| Topic | Decision |
|---|---|
| Source of truth | classi DB. Typst is an optional import source. |
| Typst access | `typst` CLI, desktop only (Linux, Windows, macOS). |
| Import | Desktop only; diff with accept/decline. |
| Point entry | All platforms. Desktop: keyboard grid. Mobile: one student at a time. |
| Grade scale | Typst-linked exam: taken from the document (read-only in classi, part of the diff). Manual exam: copied from a global template, editable per exam. |
| Scheme changes after points exist | Show which students' grades change (e.g. "Anna 3- → 4+") before applying. Same review UI as the import diff. |
| Rounding | Identical to assessio: cutoff = `round_half_up(min% × maxPoints / 100)` whole points. |
| Stored PDFs | Task sheet + unfilled Erwartungshorizont, as files in `<library>.classi/documents/`, named by SHA-256. |
| Filled Erwartungshorizonte | Desktop export to a user-chosen location. Not stored. |
| Grade written back | One `GradeEntry` per participating student, linked to the exam, updated when the result changes. |

## 1. assessio changes (repo `typst-assessio`)

Prerequisite for the Typst import. Each item gets a fixture in `tests/`.

1. **Fix grade-scale metadata (bug, reproduced).** `show-rubric` emits
   `<assessio-grade-scale>`/`<assessio-grade-config>` with the hard-coded default
   (`lib.typ:655`), and a custom `scale:` passed to `show-grade-table` never
   appears in any metadata. Make the scale that is actually used the one that is
   exported.
2. **One `<assessio-manifest>` metadata element** so classi does not depend on
   how the document imports assessio (`"/lib.typ"`, `@local/…`, `@preview/…`).
   classi reads it with
   `typst eval 'query(<assessio-manifest>).last().value' --in exam.typ --root <root>`
   (`typst query` is deprecated as of 0.15). Content:
   ```jsonc
   {
     "format": 1,                       // bump on breaking changes
     "lang": "de",
     "expectations": [                  // regular + elective + alternative, document order
       { "id": "q1-method",             // optional, see 3
         "kind": "regular",             // regular | elective | alternative
         "task": "1", "part": null, "group": "A",
         "key": "1",                    // score-dictionary key ("2a", "elective_3", …)
         "points": 1,
         "description": "Factors or transforms …",   // plain text
         "order": 1 }
     ],
     "additional": [ { "points": 1, "description": "…" } ],
     "taskGroups": [ { "id": "A", "label": "Algebra" } ],
     "electiveGroups": [ { "id": "G", "label": "…", "countedTasks": 1 } ],
     "taskTitles": { "2": "Function values" },
     "grading": { "system": "grades", "scale": [ { "grade": "1", "min": 87 } ] }
   }
   ```
   Plain-text descriptions are produced on the Typst side (`repr`-free text
   extraction) so classi does not need to port `extract_text_from_typst_ast`.
   Formulas lose detail; the stored Erwartungshorizont PDF covers that.
3. **Optional `id:` on `expectation(...)` / `elective-expectation(...)`** for
   stable matching across edits (see §4.3).
4. **Render mode via `sys.inputs`**, so classi needs no wrapper files:
   - no input → document as written (task sheet)
   - `--input assessio-mode=rubric` → only the unfilled Erwartungshorizont
     (`show-rubric(mode: "label")`-style), task bodies suppressed
   - `--input assessio-mode=rubrics --input assessio-data=<json>` → one filled
     rubric per student. `assessio-data` is either inline JSON or a path relative
     to the root; payload `{ "students": [ { "name": …, "scores": { "2a": 1.5, … }, "grade": "2-" } ] }`.
     The grade comes from classi and is printed as-is (classi is authoritative).
   Verified: `json(bytes(sys.inputs.at(…)))` works with Typst 0.15.1.
5. Remove the CLI (`extra/assessio_cli.py`, `extra/build-assessio`, ODS code)
   once classi covers export.

Scores reach the rubric per score key (`"2a"`), as today; classi sums its
expectation-level points per key for export. Per-expectation points in the
printed rubric are a possible later extension, not part of this plan.

## 2. Data model (schema 35 → 36)

All new tables get `updated_at` + the existing updated-at triggers, and indexes in
`database_indexes.dart`. Score rows use a **natural unique key** rather than
relying on autoincrement ids for identity (see §7).

**`exams`**
- `id`, `group_id` FK→groups CASCADE, `title`, `date`, `category_id`,
  `category_name` (same semantics as `grade_entries`)
- `source` `manual | typst`
- `max_points_override` real nullable (rare; normally derived)
- `grade_scheme_json` — snapshot: `{ gradeSystem: {entries…}, thresholds: [{label, minPercent}], rounding: "assessio" }`
- `typst_label_mapping_json` — Typst grade label → classi grade label, saved on first import
- `manifest_sha256`, `assessio_format`, `last_imported_at` (typst only)
- `task_sheet_sha256`, `rubric_sha256` nullable (document refs, §5)
- `created_at`, `updated_at`

**`exam_expectations`**
- `id`, `exam_id` FK CASCADE, `match_key` text (explicit id or derived, §4.3)
- `kind` `regular | elective | alternative | additional`
- `task` text, `part` text nullable, `task_group` text nullable, `elective_group` text nullable
- `score_key` text (assessio key, for export)
- `description`, `max_points` real, `sort_order`
- `U(exam_id, match_key)`

**`exam_elective_groups`** — `exam_id`, `group_key`, `label`, `counted_tasks`;
`U(exam_id, group_key)`. Task groups and titles go into `exam_task_groups`
(`exam_id`, `kind` `group|task`, `key`, `label`) for display only.

**`exam_participants`**
- `exam_id`, `student_id` FK→students CASCADE
- `status` `present | absent | excused` (absent/excused → no grade written)
- `grade_override` nullable + `override_reason` (e.g. Täuschungsversuch)
- `note`
- `U(exam_id, student_id)`

**`exam_scores`**
- `exam_id`, `student_id`, `expectation_id` FK CASCADE, `points` real nullable (null = not entered yet)
- `U(expectation_id, student_id)`, `IX(exam_id, student_id)`
- Validation in the repository: `0 ≤ points ≤ max_points`, half-point steps.

**`grade_entries`** — add `exam_id` nullable FK→exams SET NULL, and a partial
unique index `(exam_id, student_id) WHERE exam_id IS NOT NULL`. The exam owns
these rows: it creates, updates and deletes them; manual edits in the grade
editor are blocked with a "managed by exam" hint.

**Global grading scheme templates** — extend `GradeSystemDefinition`
(`grade_system_controller.dart`) with optional `thresholds: [{label, minPercent}]`.
Templates stay in the existing settings store; exams copy them into
`grade_scheme_json`.

**Device-local data (not in the DB)** — the Typst file path and root per exam
(`examId → {mainFile, root}`), in device preferences. Paths are meaningless on
other devices; mobile never shows them.

## 3. Grade computation (Dart, pure)

`lib/features/exams/domain/exam_calculator.dart`:

```
ExamResult compute(ExamStructure s, Map<expectationId, double?> scores, GradeScheme g)
```

- Regular expectations: sum.
- Elective groups: per task sum, keep the best `countedTasks` tasks.
- `additional`: added to the total; max points as declared by assessio.
- `alternative`: 0-point information rows, never scored.
- Max points: regular + counted electives (best-n of the *max* values, as assessio) + additional.
- Grade: thresholds → point cutoffs with `round_half_up`, first entry whose cutoff ≤ total.
- Incomplete (any `null` score of a present student) → no grade written yet; shown as "in progress".

Exposed per student: totals per task / part / task group / elective group, percent,
grade, and missing items. Analysis (§6) uses the same function.

**Parity with assessio**: `test/exam_calculator_parity_test.dart` runs over
fixtures generated from `typst-assessio/tests/fixtures/*.typ` (`grade-rounding.typ`
in particular): manifest + scores + expected cutoffs and grades, checked into
`test/fixtures/assessio/`. A script in `tool/` regenerates them with `typst eval`.

## 4. Typst import (desktop)

### 4.1 TypstService

`lib/features/exams/typst/typst_service.dart`, only on Linux, Windows, macOS.
- Resolve binary: settings path → bundled binary (macOS, §8) → `PATH`.
- Check `typst --version`; require a minimum version (sys.inputs + `json(bytes)`);
  check `assessio_format` from the manifest.
- `readManifest(main, root)` → `typst eval 'query(<assessio-manifest>).last().value'`.
- `compile(main, root, out, inputs)` for task sheet / rubric / filled rubrics.
- Timeouts, stderr surfaced verbatim in the UI (Typst errors are good).
- Inline `--input` data when the command line stays below a safe limit
  (Windows ≈ 32K chars); otherwise a temp file inside the root, deleted in `finally`.

Measured on `examples/basic.typ`: eval ≈ 0.6 s, compile ≈ 0.5 s.

### 4.2 Flow

1. In group → exams → "Link Typst document": pick main `.typ` file; root defaults
   to its folder, adjustable (needed when the exam imports `../vorlage.typ`).
2. classi reads the manifest, compiles task sheet + unfilled rubric to temp files.
3. First import only: grade label mapping. classi picks the group's grade system
   and pre-matches labels (exact, then leading number: `"15 (sehr gut +)"` → `15`);
   unmatched labels must be mapped manually.
4. Diff screen (§4.3). Decline → nothing changes, temp files deleted.
5. Accept → one transaction: structure, scheme, mapping, document hashes;
   PDFs moved into `documents/` *before* commit; unreferenced documents garbage-
   collected after commit; affected `GradeEntry` rows recomputed.
6. On opening a linked exam on desktop, classi re-reads the manifest in the
   background; if `manifest_sha256` differs it offers "Typst document changed – review".

### 4.3 Matching and diff

Match manifest expectations to `exam_expectations.match_key`:
1. explicit `id` → `id:<id>`
2. otherwise `kind|task|part|normalized description`
3. unmatched leftovers in the same `kind|task|part`: paired by order and shown
   as "changed (text)", flagged as uncertain so the user can split them into
   remove + add.

Change list, with consequences:

| Change | Consequence shown |
|---|---|
| expectation added | students get empty scores → exam back to "in progress" |
| expectation removed | **warning** if points exist: "N scores will be deleted" |
| max points lowered | lists students whose points now exceed the max (clamped on accept) |
| description / order / title changed | none |
| elective `countedTasks` changed | grade changes |
| grade scale changed | grade-change preview per student |
| new/renamed Typst grade label | requires mapping before accept |

Every diff that changes grades ends with the shared "grade changes" preview.

## 5. Document storage

- Location: `<library>.classi/documents/<sha256>.pdf`. DB holds only hashes.
  Content-addressed → immutable, deduplicated; re-import of an unchanged PDF
  writes nothing.
- GC: after each accepted import and on exam deletion, remove files no exam
  references.
- **Sync**: `library_backup_service.dart` currently archives only `data.db` +
  fixed sidecars (`artifactPathsFor`) and *deletes the package directory* on
  restore (`:207-211`). Extend `_artifactEntryNamesFor` / restore to include
  `documents/**`. Without this, files never reach other devices and are wiped on
  restore.
- Files are not encrypted (no student data). Note: the unfilled
  Erwartungshorizont is then readable in the WebDAV ZIP before the exam is
  written. Encrypting with the library key is a possible follow-up.
- Viewing: in-app PDF viewer on all platforms (new dependency, e.g. `pdfrx`;
  the existing `pdf` package only writes PDFs). Opened from the exam screen
  and from the point-entry screens ("show Erwartungshorizont").
- Android: the package lives in app-specific storage already, so no extra
  permissions.

## 6. UI

**Group detail → "Exams"** list (date, title, status: in progress / complete,
average, distribution sparkline). Create manually, or (desktop) from Typst.

**Exam screen**
- Structure: tasks → parts → expectations with max points. Editable for manual
  exams on all platforms; read-only with "managed by Typst" for linked exams.
- Grading scheme: thresholds with live point cutoffs; template picker for
  manual exams; read-only for linked exams.
- Documents: task sheet, Erwartungshorizont.
- Results: per student total, %, grade, status; grade distribution.
- Desktop actions: re-import, export filled Erwartungshorizonte.

**Point entry – desktop grid**: rows = students, columns = expectations grouped
by task, sticky headers with max points; Tab/Enter/arrow navigation, typing a
number commits; `,` and `.` both accepted; cell turns red above max; per-row
total, % and grade live.

**Point entry – mobile, per student**: one student at a time, expectations as a
list with stepper / number field (half steps), running total and grade at the
bottom, "next student" (stack order). Same screen usable on desktop.

**Export filled Erwartungshorizonte (desktop)**: choose "one PDF" or "one PDF per
student" → save dialog (`file_picker`) → `typst compile` with
`assessio-mode=rubrics`. Only complete, present students; others listed.

**Global settings**: grade system editor gets a "thresholds" section, turning
a grade system into a grading scheme template.

## 7. Sync constraints

Sync is whole-library WebDAV export with a revision check (`MergeService` is not
called from app code). Consequences:
- Point entry on phone and desktop works **in turns** (enter → sync → continue
  elsewhere), not concurrently. Fine for the intended workflow; documented in UI
  copy.
- The PDF files add to every upload → keep only current documents (GC above).
- Should the three-way merge ever be enabled, two existing issues would hit this
  feature and must be fixed first:
  - `_rowsEqual` compares with `!=`, which is identity for `Uint8List` BLOBs (not
    used here since PDFs are files, but relevant for any future BLOB).
  - autoincrement ids created on two devices collide and "newer wins" silently
    drops rows. `exam_scores` must then merge on `(expectation_id, student_id)`.

## 8. Platform risks – spike first

**macOS sandbox.** Both `.entitlements` files enable `app-sandbox`. Launching a
Homebrew `typst` is likely to fail or not see the exam folder / Typst packages
(child processes inherit the sandbox). Spike before building §4:
1. `Process.run` on `/opt/homebrew/bin/typst --version` from the sandboxed app.
2. Bundle `typst` as a signed helper (`com.apple.security.inherit`), grant the
   Typst root folder via folder picker + security-scoped bookmark, compile an
   exam that imports a sibling file and an `@preview` package.
3. Outcome decides: bundled binary on macOS, or Typst features Linux/Windows only.

Linux native and Windows have no such restriction. (The Flatpak manifest is being
removed; a Flatpak would need a bundled `typst` too.)

## 9. Implementation order

1. **assessio**: grade-scale fix, `<assessio-manifest>`, `id:`, `assessio-mode`; fixtures.
2. **macOS spike** (§8), in parallel with 3.
3. **Schema 36** + repositories + `ExamCalculator` + parity tests.
4. **Manual exams end to end**: exam screen, scheme templates, mobile + desktop
   point entry, `GradeEntry` write-back, grade-change preview. Usable without Typst.
5. **Document storage + sync** of `documents/`, PDF viewer.
6. **Typst import** with diff, label mapping, change detection.
7. **Export** of filled Erwartungshorizonte.
8. **Analysis**: item difficulty (mean % per expectation/task), per-student task
   profile, distribution, comparison across a group's exams.
9. Retire the assessio CLI.

Steps 3–4 deliver value on their own; Typst comes on top.

## Implementation status (2026-11-07)

Implemented in classi and typst-assessio (uncommitted). Deviations from the
plan above:

- **Platforms.** Typst import/export runs on Linux and Windows
  (`TypstService.isSupportedPlatform`); macOS is dropped (sandbox, §8) and
  only enters points, like Android. Windows is enabled but untested.
- **Rendering without `sys.inputs` modes in the document.** assessio cannot
  hide a document's own content from inside the library. Instead classi writes
  a temporary wrapper next to the exam (`.classi-render-*.typ`, always
  deleted) that `include`s the exam with assessio output suppressed and calls
  `render-blank-rubric` / `render-student-rubrics`. Those mark the first
  rubric page with `<assessio-rubric-start>`; classi drops the exam pages
  with `typst compile --pages N-`. Student data goes inline through
  `--input assessio-data=…`, or a deleted-afterwards temp file above 100 KB.
- **Manifest.** `<assessio-manifest>` is emitted by every `task()`; it also
  carries assessio's own `max_points` and per-grade point `cutoffs`, which the
  parity tests and the import screen compare against classi.
- **Per-expectation scores.** Score keys are per expectation (`2a.3`,
  `elective_3.1`, `additional.<idx>`), so the printed rubric shows classi's
  points exactly.
- **Group metadata as JSON.** Task groups, elective groups and titles live in
  `exams.structure_json` instead of their own table.
- **Templates.** Grade systems in the settings got an optional "Exams: from %"
  per grade; manual exams copy those thresholds (else NRW defaults by size).
- **Score steps.** Any decimal is accepted; the per-student screen steps by 0.5.
- **CLI not deleted.** `extra/assessio_cli.py` is marked deprecated in the
  README/CHANGELOG but left in place because it contains uncommitted work.

Code: `lib/features/exams/` (domain, data, typst, ui), schema 36, routes
`/groups/:g/exams/:e[/students/:s]`. Tests: `test/exam_*_test.dart`;
`tool/generate_assessio_fixtures.sh` regenerates the parity fixtures.
